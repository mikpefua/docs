# `GET /v1/global-collection/transactions/{transactionId}`

Retrieve the status of any initiated mobile money transaction. Use this endpoint to confirm whether a collection was successful, pending, or failed — keeping your records accurate and your customers informed.

<CodeGroup>
```bash Request
curl --request GET \
  --url https://api.nomba.com/v1/global-collection/transactions/a822e327-4bcd-40ec-ac61-ed3622eac000 \
  --header 'Authorization: Bearer <token>' \
  --header 'accountId: <accountId>'
```

```json Response
{
  "code": "00",
  "description": "Successful",
  "data": {
    "transactionId": "a822e327-4bcd-40ec-ac61-ed3622eac000",
    "coreUserId": "xxxx-xxxx-4402-97c0-6c3824cxxxxx",
    "account": "0980802918",
    "status": "PENDING",
    "amount": 10.00,
    "currency": "CDF",
    "vendor": "MPESA",
    "gatewayCode": "AWAITING_CUSTOMER_APPROVAL",
    "gatewayMessage": "Awaiting customer approval"
  }
}
```
</CodeGroup>

#### Path parameters

<ParamField path="transactionId" type="string" required>
  The `transactionReference` returned when the inflow was initiated.
</ParamField>

#### Response body

<ResponseField name="transactionId" type="string" required>
  The unique collection transaction ID.
</ResponseField>

<ResponseField name="coreUserId" type="string">
  The Nomba account ID that received the collection.
</ResponseField>

<ResponseField name="account" type="string">
  The customer's mobile money account (phone number).
</ResponseField>

<ResponseField name="status" type="string" required>
  Current status of the collection.

  | Value | Terminal | Description |
  |---|---|---|
  | `PENDING` | No | Payment prompt sent; awaiting the customer's approval on their phone. |
  | `APPROVED` | No | The customer approved the payment, but the credit has not landed yet. Keep polling. |
  | `SUCCESS` | Yes | The payment is complete and the funds have been credited. |
  | `FAILED` | Yes | The collection could not be completed. |
  | `PENDING_APPROVAL` | No | The provider never returned an outcome within the polling window. Rare; contact support with the `transactionId`. |

  <Warning>
    `APPROVED` is **not** a completed collection. It means the customer approved the charge on their
    phone; the funds are still being credited. Only `SUCCESS` is a settled payment. Do not release
    goods or services on `APPROVED`.
  </Warning>
</ResponseField>

<ResponseField name="amount" type="number" required>
  The collected amount.
</ResponseField>

<ResponseField name="currency" type="string" required>
  The currency of the collection.
</ResponseField>

<ResponseField name="vendor" type="string">
  The mobile money network the collection was requested on, echoing the `topupVendor` you sent.
</ResponseField>

<ResponseField name="gatewayCode" type="string">
  A stable, machine-readable outcome. **Branch on this**, not on `gatewayMessage` -- the message
  wording may change, the code will not.

  | Value | Meaning | What to do |
  |---|---|---|
  | `AWAITING_CUSTOMER_APPROVAL` | The prompt has been sent and the customer has not approved it yet. | Keep polling, or wait for the webhook. |
  | `CREDIT_IN_PROGRESS` | The customer approved; the credit is still settling. | Keep polling until `SUCCESS`. |
  | `PAYMENT_RECEIVED` | The collection settled. | Fulfil the order. |
  | `WRONG_MOBILE_MONEY_NETWORK` | The phone number is not registered on the `topupVendor` you selected. | Fix the network for that number and retry. Call [Fetch Inflow Providers](/docs/products/global-collections/fetch-drc-inflow-providers) for valid values. |
  | `TEMPORARILY_UNAVAILABLE` | The payment was never attempted — nothing was charged and the customer saw no prompt. | Retry later with a **new** `idempotencyKey`. Do not treat it as a decline. |
  | `PAYMENT_DECLINED` | The payment was not completed. The provider gives no reason for most declines; the common cause is an unfunded customer wallet. | Ask the customer to fund their wallet and retry. |
  | `STATUS_UNAVAILABLE` | The outcome could not be determined. | Contact support with the `transactionId`. |
</ResponseField>

<ResponseField name="gatewayMessage" type="string">
  A human-readable version of `gatewayCode`, safe to show to an operator. Do not parse it.
</ResponseField>
